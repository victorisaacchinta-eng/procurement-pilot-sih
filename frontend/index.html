Cross-bid collusion screen

Bids that move together get flagged together.

Every bidder on a tender is compared with every other: quotes clustered too tightly, a cover bid parked far above the benchmark, submissions minutes apart, the same registered address.

Who decides what.

The split of work is the product. Code handles anything with a right answer, the model explains, and a named officer carries the decision.

Code

Rules first

EMD, documents, turnover and price are pass or fail. Code decides those, so the model never guesses a number.

Model

It explains, it never approves

The reasoning layer reads the check results, then names every flag in plain language. The score and verdict are computed, not written.

Officer

A name on every decision

Decisions are stamped with who and when. Overruling a flagged bid takes a senior approver and a written reason, both kept in the audit log.

The ten checks.

Each check returns pass, flag or fail with a sentence that names the real numbers. A pass earns the full weight, a flag half, a fail nothing. A fail on EMD, documents or debarment caps the score at 45.

* Registry lookups run against a simulated GST registry in this prototype and say so on every result. Check-digit validation is real.

Questions officers ask.

Short answers. The workstation shows each one in practice.

What does the model actually see?

The tender title and specification, the bidder name, and the results of the ten checks. It does not receive bank details or raw bid documents, and it cannot change the score or the verdict.

What happens if the model is down?

The ten checks and the score still run, because they are plain code. The recommendation falls back to a deterministic summary and says so on screen. The model provider is a setting, so it can point at an Indian or self-hosted model without code changes.

Can someone quietly approve a flagged bid?

No. Qualifying a bid the system did not mark compliant needs a senior approver and at least 30 characters of written reason. An officer gets refused by the server, not just the screen, and every override is kept in the audit log.

Who can see and export the audit log?

Any signed-in user can view it. Only an admin can export it, and every export is itself written to an access log.

How long are records kept?

180 days by default. After that the bidder's identity and free-text notes are irreversibly anonymised while the scores stay for audit continuity. The period is configurable.

Is the GSTIN lookup live?

Not yet. The prototype validates GSTIN structure and the check digit for real, then matches the legal name against a simulated registry and labels every result as simulated. Going live needs a GST data provider key and one API call.
